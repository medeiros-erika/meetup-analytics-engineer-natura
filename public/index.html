Quatro tipos de fato. Qual jeito de escrever cada um pede?

Transacional

Uma linha por evento, que não muda depois de acontecer.

Clique para virar

Uma foto de cada entidade por período.

Clique para virar

Insert por partição

No case: fact de obrigação consolidada, particionada por data de referência.

Snapshot acumulado

Uma linha por processo, atualizada a cada marco.

Clique para virar

Merge

sk_

Chave da versão. É o que a fato guarda.

nk_

Chave natural, estável entre versões.

ts_inicio / ts_fim

Janela da vigência. Fim nulo é a versão aberta.

hash

Dos atributos versionados. Mudou, abre versão.

Case · Snapshot de obrigações

O snapshot lembra o que a origem esquece

Cada intermediate de obrigação ganha um snapshot SCD2 com strategy check: o que o cliente devia em qualquer dia, por produto.

dc_status_obrigacao_financeira dt_compensacao dc_tipo_bloqueio_advertencia dc_evento_contrato fl_debito_cobravel ?
-- ilustrativo {% snapshot snp_int_obrigacao_financeira_cartao_intraday %} strategy = 'check' check_cols = [colunas versionadas] -- dias de atraso ficam fora

Pausa para pensar

A decisão filtra débitos cobráveis, mas fl_debito_cobravel ficou fora do check. O que quebra?

O histórico existe, mas não explica a decisão: o snapshot não guardava o filtro que ela usava. Controle permanente: a flag entrou no snapshot. A lista de check_cols é contrato.

O snapshot também gera dado

No cartão, a conta quitada some da origem sem data. A data da baixa vem do snapshot.

Case · Motor de decisão · simulador

Roda toda hora, grava só a mudança

Evite

SCD2 na fato horária

Versionar a cada execução, ou com um campo que muda sozinho, gera microvigências: versões de uma hora que não contam nada.

Faça

Hash do estado de decisão

Grave só quando o hash difere do último estado. Nulos viram string vazia antes do hash, igual em todas as camadas.
